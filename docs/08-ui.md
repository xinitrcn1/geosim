# 08 — UI

The player interface is a heads-up display over the world map (docs/07). The
first client (`src/client`, target `geosim`) implements the visual style,
renderer, top bar, agent bars and alert feed described here; the map, the
inspector, the drawer tabs and the action panels are still to come.

## Visual style

These principles replace the earlier "statistics office" look. Inspiration:
Cities: Skylines 2.

- **Everything is a rectangle.** Square corners, never rounded. Panels,
  buttons, separators, glyphs and the map are all instanced quads.
- **Two kinds of panels:**
  - **Opaque** — flat, solid squares for the few elements that must always be
    visible and readable (the top bar).
  - **Translucent** — frosted glass for anything that can be dismissed or
    ignored (agent bars, alerts, tooltips, future inspector/drawer). They
    Gaussian-blur what is behind them and tint it blue.
- **Colour scheme:** soft blues (`src/client/style.hpp`). White text, white
  monochrome emoji used as icons. **Red text = bad, green text = good**
  for the player, used only on indicators and alerts; neutral values stay white.
- **Icons are emoji**, not images: no icon code, no texture other than the
  glyph atlas. Flags are the nation's emoji flag.
- **Typeface:** Source Sans 3 (variable font, any weight on the `wght` axis;
  the HUD uses 400 and 600). Sizes 12 / 14 / 15 pt at 1× scale.
- **Scaling:** UI scale = SDL3 window display scale (pixel density × content
  scale) × `--ui-scale`; layout metrics are points multiplied by that scale.
- **Numbers carry units** and a hover tooltip with their definition.


- **Top bar** (always top-left, opaque): the controlled agent's flag/symbol
  and nation, the current date, SimCity 4-style time controls (pause and
  speeds 1–5), one button per important action (policy, budget, diplomacy,
  military, politics) and one per map filter (political, economy, epidemic,
  energy, unrest; exactly one active).
- **Agent bars** (below, translucent): one per agent the player controls —
  for now the nation's executive and central bank — with indicators coloured
  green / red when good / bad for the player.
- **Alerts** (below the agent bars, translucent): journal events (wars,
  peace, coups, regime changes, elections, defaults, insurgencies, disasters…
  worldwide; disputes, agreements, no-confidence votes, court rulings only for
  the player's nation), newest first, each dismissable.

- **Filters:** filter tree, display mode selector, stratum lens, reference date.

  matrices), *Diplomacy* (relations, treaties, negotiations).

## Interaction patterns

- **Hover** any number → tooltip with its definition (implemented for the
  agent-bar indicators and the top-bar buttons).
- **Keyboard:** Space / P toggles pause (resumes the last speed), 0 pauses,
  1–5 pick a speed, + / − step the speed, Ctrl+Q quits. Every action will be
  reachable by keyboard; a command palette (`Ctrl+K`) is planned.
- **Mouse:** click buttons (press and release inside), wheel scrolls the
  alert list. `ui_context::wants_mouse()` tells the future map when the
  pointer is over a panel.
- Planned: click a number → Trace tab; Shift+click regions → comparisons in
  Charts; the override flow (inspector → agent → *Advise / Direct / Force* →
  policy editor → *Commit*); sortable tables with copy as TSV.

## Time controls

| Control | Speed | Days per second |
|---|---|---|
| ⏸ | 0 | paused |
| 🐌 | 1 | 1 |
| 🐢 | 2 | 2 |
| 🦙 | 3 | 4 |
| 🐆 | 4 | 8 |
| 🚀 | 5 | unthrottled (as fast as the simulation runs) |

The speed button's tooltip shows the measured rate.

## Implementation

### Modules (`src/client`)

| File | Role |
|---|---|
| `main.cpp` | command line, assets directory lookup |
| `app.*` | SDL3 window, event loop → `ui_input`, frame orchestration, resize / display-scale handling, scripted input for headless checks |
| `vk_context.*` | Vulkan 1.3 instance, device, swapchain, frames in flight, buffer/image helpers |
| `ui_renderer.*` | quad pipelines (one per material), scene image, blur chain, glyph atlas upload, screenshots |
| `ui_draw.hpp` | `quad_instance`, `material`, `draw_list`, layers |
| `text.*` | FreeType glyph atlas, variable-font weights, shaping-lite, emoji flags |
| `ui_context.*` | immediate-mode core: hit testing, panels, text, buttons, tooltip |
| `ui_layout.*` | the HUD: top bar, agent bars, alert feed |
| `sim_runner.*` | the simulation thread, indicators, journal requests |
| `style.hpp` | colours and metrics |
| `shaders/*` | GLSL, compiled with glslangValidator at build time and embedded as SPIR-V arrays |

The UI is **immediate-mode**: the HUD is rebuilt from the simulation every
frame; only the pressed button, scroll offset and alert list persist.
Dear ImGui may be used **only** for developer overlays behind a compile-time
option; it does not ship in the player UI.

### Rendering

Vulkan 1.3 with dynamic rendering and synchronization2 (no render passes).
Every element is one instance of a single instanced-quad vertex format
(`quad_instance`, 48 bytes: rect, uv / material parameters, colour, border
colour, border width, flags); the vertex shader expands 6 vertices from
`gl_VertexIndex`, so there is no vertex buffer besides the instance buffer.

- **Materials** are pipelines sharing that vertex shader and instance format,
  each with its own fragment shader: `ui` (flat, frosted, glyph and scene-copy
  modes selected by `flags`) and `map_placeholder`. A future chart is a new
  material: add `shaders/chart_x.frag`, an entry in `material` and in the
  material table in `ui_renderer.cpp`, and push one quad whose `u0..v1` carry
  its parameters. Consecutive instances of the same material are one draw.
- **Frame:**
  1. *Scene pass* into an offscreen image: the map (placeholder) and the
     opaque layer (top bar and its text).
  2. *Blur:* scene → ½ → ¼ resolution (bilinear 2×2 box per step), then a
     separable Gaussian (σ = 3 texels at ¼ resolution ≈ 12 px, 15 taps)
     horizontal and vertical.
  3. *Final pass* on the swapchain: a copy of the scene, then the overlay
     layer: frosted panels sample the blurred image under their rect and mix
     in their tint (tint alpha = strength), then text and tooltips.
  Translucent panels blur the scene only, not other translucent panels
  overlapping them (as in C:S2, panels rarely overlap).
- The UI works in display (gamma) space on a UNORM swapchain, so the colours
  in `style.hpp` are the sRGB values on screen.
- Validation: `--validation 1` or `GEOSIM_VK_VALIDATION=1` enables
  `VK_LAYER_KHRONOS_validation`; the message count is printed at exit and
  automated runs (`--frames`) exit with code 3 on validation errors.

### Text

- **Fonts** (`assets/fonts`, all SIL OFL 1.1, licences alongside):
  Source Sans 3 (`SourceSans3-Variable.ttf`, google/fonts) and Noto Emoji
  (`NotoEmoji-Variable.ttf`, the monochrome Noto emoji, google/fonts).
- **Rasterisation:** FreeType into one 1024² R8 coverage atlas (shelf packer,
  glyphs cached per face, size and glyph; cleared on display-scale change or
  when full). Both fonts are variable: one FT_Face per (family, weight) is
  instantiated from the in-memory file with `FT_Set_Var_Design_Coordinates`
  on `wght`, so any weight can be requested (`font_weight{550}`).
- **Shaping-lite:** UTF-8 → codepoints; per-codepoint fallback (emoji font
  first for pictographs and symbols, then the text font); horizontal advances;
  variation selectors and ZWJ skipped; regional-indicator pairs → the emoji
  font's GSUB ligature (lookup type 4, parsed directly), which gives the
  flags. No kerning, ligatures, complex scripts or bidi yet. HarfBuzz is not
  installed on the dev machine; when CMake finds it, it is linked and
  `GEOSIM_HAS_HARFBUZZ` is defined so `text_system::shape` can be replaced
  without touching callers (needed for localisation / RTL).
- **Emoji are monochrome** (white, tinted like text). Colour emoji
  (CBDT / COLR) are not supported: they would need an RGBA atlas.

### Simulation data

The client links `geosim_sim`, builds the scenario (`--scenario`, default
`2020`) on a dedicated simulation thread and advances days at the selected
speed. The simulation never waits for the UI:

- **Scalars** (the tick, nation floats) are read by the UI thread directly
  from the DCON SoA while the simulation writes them. Values may be stale or
  from different days; ids are bounded by the SoA, so a stale id reads stale
  data, never out of bounds. This is accepted for display.
- **Lists** (anything whose storage can move) are requested with a
  `std::future`: the job runs on the simulation thread at its sync point
  between two days. The alert feed requests journal entries since the last
  scanned tick at most every 250 ms (`sim_runner::request_journal`).
- **Indicators** of the player's nation (`--nation`, default USA):
  Government — incumbent's vote share, real GDP growth (first year: run mean
  vs 2019, as `sim::summarize`; then trailing 12 months vs the year before,
  from the `acc_*` accumulators), unemployment, change in the budget balance
  (% of GDP, from day 30), days to the election; Central bank — CPI inflation
  (same window as GDP), policy rate, 10-year yield, real exchange rate.
  Good / bad thresholds are in `sim_runner.cpp`.

This replaces, for now, the planned sim *snapshot* and *command queue*
([09](09-engine-architecture.md#threading)): the UI does not write to the
simulation yet except the speed.

### Build and run

```
cmake -S . -B build/client -DGEOSIM_BUILD_CLIENT=ON -DGEOSIM_USE_DCON=ON
cmake --build build/client --target geosim
build/client/src/geosim [--nation USA] [--speed 0..5] [--ui-scale 1.5]
```

Needs SDL3, Vulkan 1.3 (loader, headers, `glslangValidator`) and FreeType.
Headless check (no display, e.g. with Mesa lavapipe):

```
SDL_VIDEODRIVER=offscreen build/client/src/geosim --validation 1 \
    --frames 60 --speed 5 --until-day 200 --screenshot out.ppm \
    --inject "30:click:226,25;60:resize:1100,700"
```
